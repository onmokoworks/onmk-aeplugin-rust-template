# パラメータと識別子の互換性

[English](./parameter-compatibility.md)

保存された AE プロジェクトは、エフェクトを **マッチネーム** で、パラメータ値を **インデックス**
（`params.add` を呼んだ順。1から始まり、0は入力レイヤー）で保存します。エクスプレッション、
プリセット（`.ffx`）、スクリプトもインデックスや名前でパラメータを参照します。一度でも保存済み
プロジェクトで使われたプラグインでは、以下を公開 API として扱ってください。

## リリース後に変えてはいけないもの

| 項目 | 理由 |
|---|---|
| マッチネーム（`AE_Effect_Match_Name`） | エフェクトの識別子。変えると別エフェクト扱いになり、古いプロジェクトでは見つからないエフェクトになる |
| パラメータの順序 | 値はインデックスで復元されるため、並べ替えると古い値が別のコントロールに入る |
| パラメータの削除 | 以降のインデックスがすべてずれる。削除せず非表示にする（枠は残して使わない） |
| パラメータの型 | スライダーをポップアップやチェックボックスに変えると、不正な値が復元されるか読み込みに失敗する |
| 既存のポップアップ値の意味 | ポップアップの値はラベルではなく1始まりの番号 |
| 同じマッチネームの2つのプラグイン | AE はどちらか一方しか読み込まない。インストーラはこの状態を拒否する |

## 変更してよいもの

- 新しいパラメータを **末尾に追加** する。古いプロジェクトでは新パラメータの既定値が使われる。
  `// Appended to preserve indices.` のようなコメントを添える。
- **表示名** を変える（`params.add` のラベル、`Property::Name`、`Property::Category`）。
  名前でパラメータを探すスクリプトは更新が必要になり得るので、リリースノートに書く。
- **既定値** を変える。新しい既定値は新しく適用したインスタンスにだけ効き、保存済みプロジェクトは
  保存された値を保つ。古いプロジェクトで旧既定値の挙動を保つ必要がある場合は、バージョン用の
  パラメータかシーケンスデータを使う。
- スライダー範囲を広げる。狭めると保存値が切り詰められることがある。
- ポップアップの選択肢を **末尾に追加** する。既存の選択肢は同じ番号のまま残し、選択肢の数
  （`set_options` に渡す長いリスト）を更新する。選択肢の名前変更は意味が同じ場合だけにする。

## ポップアップ

- 値は **1始まり**。最初の選択肢が1。`set_default` に渡す既定値も1始まりで、
  `1..=選択肢数` の範囲にする。
- どのレイヤーに適用しても安全な既定値を選ぶ（破壊的なモードではなく「通常」のモードなど）。
- 未知の値に備える。新しいバージョンで保存したプロジェクトには、このビルドが知らない番号が
  入り得る。描画を失敗させずに既定値へ戻す（AeMinimal の `Mode::from_popup`）。
- ラベル一覧は1つの定数にまとめ、数と既定値の整合を保つ（`Mode::LABELS`、`Mode::DEFAULT`）。

## レイヤーパラメータと SmartFX の checkout id

- レイヤーパラメータの AE インデックスは `SmartPreRender` の `checkout_layer` で使う。
  パラメータ一覧の隣に名前付き定数として置き（AeMinimal の `PARAM_BLEND_LAYER`）、
  変更は末尾追加と一緒の場合だけにし、並べ替えでは変えない。
- checkout id は自由に決めてよく、`SmartPreRender` と `SmartRender` で一致していればよい。
- レイヤーパラメータが空なのは通常の状態。checkout の失敗は「レイヤーなし」として扱う。

## PiPL の安定性

- マッチネーム、エントリポイント名、PiPL の kind はエフェクトの生涯を通じて変えない。
  リリース時は `AE_Effect_Version` を上げる。
- グローバル out flags を気軽に変えない。AE はこれをキャッシュし、`DeepColorAware` /
  `FloatColorAware` / `SupportsSmartRender` などを変えると既存プロジェクトの描画方法が変わる。
  AE は PiPL と `GlobalSetup` のフラグの一致を確認する。テンプレートは両方を `build.rs`
  から生成するため食い違わない。
- Windows では非 ASCII の名前もバイト単位でそのまま埋め込まれる（`crates/ae_plugin_build` 参照）。

## リリース前チェックリスト

1. 前回リリースと `params.add` の並びを比較する。末尾追加だけか。
2. マッチネームは同じか。パラメータの型は同じか。
3. ポップアップの新しい選択肢は末尾だけか。既定値は範囲内か。
4. 前回リリースで保存したプロジェクトを開き、すべての値を確認する。
